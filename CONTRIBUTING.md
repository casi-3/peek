# Contributing

Thanks for your interest in improving Peek! Issues, ideas and pull requests are welcome.

## Getting started

```bash
git clone https://github.com/casi-3/peek
cd peek
npm install
cp config.example.json config.json   # then edit it, or use the in-app setup window
npm start
```

On first launch a setup window lets you enter your Frigate host and MQTT broker,
no file editing required.

## Building

```bash
npm run dist        # current platform
npm run dist:mac    # macOS .dmg + .zip
npm run dist:win    # Windows installer + portable
```

## Guidelines

- The app is plain Electron + vanilla JS, no framework, so keep it lightweight
  and avoid new dependencies where you can.
- Match the existing style and keep each change focused on one thing.
- Never commit `config.json` or any personal data; it is gitignored.
- For larger changes, open an issue or a discussion first so we can align.

## Code style

Peek keeps a clean, uniform codebase. A pull request that already follows these
points can be merged straight through, so you keep full credit on it.

- No inline comments. Prefer clear names and small functions over explaining in
  a comment.
- No dead or commented-out code, no debug logging left behind, no unused
  variables or imports.
- No generated boilerplate, and no tool or assistant markers in the code or in
  commit messages, such as "Generated by" notes or automated co-author trailers.
- Plain ASCII punctuation: straight quotes and regular hyphens, not long dashes.
- All user-facing text in English.

A change that does not follow these may be reworked into a release commit
instead, with you credited by name in the release notes and as a co-author.

## Reporting bugs

Open an issue with your OS, Frigate version, and steps to reproduce. Logs from the
terminal (when run with `npm start`) help a lot.
